# APK 本地后端架构约束

## 目标

APK 是一个本地完备应用，和 Web 端共用同一套 Web UI。服务器同步只是附加能力，不是 APK 可用性的前提。

## 基本原则

- 前端只维护一套 `templates/index.html`、`web_static/app.css`、`web_static/app.js`。
- Web 服务器后端和 APK 本地后端实现同一套 `/api/...` 合约。
- 新功能先定义 API 请求和响应，再分别补 Web 后端和 APK 本地后端。
- APK 的本地数据是主路径：歌曲库、歌词、学习状态、选段、调号、导入文件都必须能在无服务器时工作。
- 服务器同步只做导入、刷新或备份，不应成为页面加载、保存、练习的必需条件。

## APK 与 Web 的分工

Web UI 负责：

- 页面布局、播放器、歌库、上传/输入歌词、生成页和设置页。
- 调用 `/api/...` 完成读写。
- 只在平台能力无法用标准 Web API 完成时调用 Android Bridge。

APK 本地后端负责：

- 拦截 `/api/...` 请求并返回与 Flask 后端一致的 JSON。
- 在 App 私有目录保存歌库、歌词、音频、生成工作源、任务列表和练习状态。
- 提供 Android 文件选择、文件复制、音频 URI 处理等平台能力。
- 用本机保存的 OpenAI 兼容配置直接测试接口和生成 ruby 歌词，不经过同步服务器。
- 在无同步服务器时直接支持 LRCLIB 搜索/预览；其他歌词源可以继续作为 Web 后端或后续 APK provider 扩展。
- 可选连接服务器同步，但同步失败不能破坏本地使用。

服务器后端负责：

- Web 端完整功能。
- APK 可选同步源。
- 扩展歌词源、批量任务、音频转换等不属于 APK 基础本地可用性的能力。

## API 合约维护

新增功能时按这个顺序做：

1. 在测试里写清楚 Web UI 需要的 `/api/...` 合约。
2. 在 Flask 后端实现或确认已有实现。
3. 在 APK 本地后端实现同一合约。
4. 如果涉及文件选择或权限，再添加 Android Bridge 方法。
5. 验证 Web 端和 APK 端都能通过同一套 UI 操作。

## 难度分级

- 纯 UI 改动：通常只改共享 Web UI，APK 会随打包同步。
- 读取类接口：APK 返回同结构 JSON 即可。
- 普通保存类接口：需要 Web 后端和 APK 本地后端各保存一份数据。
- 文件/音频上传：APK WebView 拿不到 multipart 请求体，应通过 Android Bridge 选择并复制文件。
- 联网歌词和 AI 生成：APK 至少要有一条不依赖同步服务器的本地路径；新增 provider 时不能影响基础离线练习。
- 多设备同步和冲突处理：必须单独设计，不要混进基础本地功能。

## 同步规则

- 同步入口可以保留在设置页或 APK 专属区域。
- 同步失败只显示错误或重试状态，不影响本地库读写。
- 同步不能覆盖未处理的本地写入，除非后续明确实现冲突策略。
- 默认不要把用户的服务器地址硬编码成 APK 必需配置。
- APK 默认同步后端地址必须为空；只有用户主动填写或读取云端配置后，才能访问可选同步后端。
- APK 包内 HTML、JS 和 Android 代码不应包含维护者私有内网地址作为默认值或 placeholder。
- APK 生成页的工作源保存、对齐、生成任务、预览生成结果、发布正式歌词都必须能在未配置同步后端时工作。
